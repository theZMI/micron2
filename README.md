# Micron Engine 2

## Что это за движок:
Micron - это простой framework написанный на PHP и ориентированный на компонентную модель построения сайта (HMVC).

## Документация:
Полная документация открывается на самом сайте: `/manual` (тексты разделов - `tpl/manual/_pages/*.php`, примеры кода в них выводятся функцией `DocCode()`).

## Структура движка и как с ним работать:
```
📁 core - ядро движка
   📁 сonfig
   📁 migrations - миграции БД (см. ниже)
   📁 func - ф-ии хелперы (для отправки email-ов, для отображения сообщений, для дебага, форматирвоания, работы с текстом и пр.)
   📁 init - тут происходит инициализия базы, роутинга, логгера ошибок и пр.
📁 i - js/css-файлы, картинки, файлы для загрузки (doc, xl, apk и что угодно другое что можно считать asset-ами)
📁 lang - переводы старниц/компонентов
📁 lib - библиотеки установленные не через composer
📁 model - классы для работы с БД (по технологии ActiveRecord т.е. формат вида $user1001 = new UserModel(1001); // Запись из таблицы users с id=1001)
📁 src - php-код страниц/компонентов (controllers)
📁 tmp - скомпилированные js/css-ки и всякие временные файлы (в public должно быть доступны только папки вида _auto_mege_css_js, но не сама папка tmp так как в ней текстовые логи ошибок и их отбражение - это небезопасно)
📁 tpl - шаблоны страниц/компонентов (views)
📁 vendor - библиотеки установленные composer-ом
📄 .env - файл с переменными зависящими от окружения (должно быть для production-а одни, для local-ки другие). Например подключение к БД, или домен сайта
📄 .gitignore - список тех файлов которые должны игнорироваться при коммитах проекта в git
📄 composer.json - библиотеки которые нужно установить в vendor для работы сайта (главный список)
📄 composer.lock - весь список с конкретными версиями и зависимостями установленными в vendor
📄 favicon.ico
📄 index.php - входная точка в движок. Все запросы на сайт (кроме запрос картинок и файлов) идут сюда, а этот файл уже подключает движок из core и нужную страницу из src+tpl
📄 README.md - хелп который вы сейчас читаете
```
## Что есть из коробки:
- Главный шаблон для сайта (шапка, футер)
- Админка
- Заготовка для пользовательского кабинета
- Пакеровщик (webpack) для работы с sass, less, typescript
- Мультиязычность (каталоговая модель)
- Работа с БД (DbSimple и простые модели)
- Инструменты для debug-а (debug-panel, простая ф-я распечатки -> Xmp, раздел в админке с логами, логирование ошибочных запросов к БД, настройки для DEBUG_MODE)
- Подключён Bootstrap 5 для дизайна
- Подключён и настроен Роутинг (core/init/router) который по умолчанию соотносит uri по правилу: site.com/example -> (src/example.php + tpl/example.php)
- Подключён Vue3 для создания сложных веб-приложений
- Подключён шрифт PTSans как основной

## Настройка:
- Переименуйте .env.example в .env и задайте внутри правильные данные для вашего текущего сайта (siteRoot, подключение к БД, режим отображения ошибок, домен для cookie и пр.)<br>
  Обязательно задайте `ADMIN_DEFAULT_PASSWORD` (без него первый админ не создастся) и `CRON_SECRET` (`openssl rand -hex 32`)<br>
  Все ключи и пароли (почта, SMS, push, telegram, платёжные системы) хранятся только в .env, в коде их быть не должно
- Сделайте в терминале `composer install` чтобы установить зависимости в папку /vendor
- (необязательно) Также в терминале зайдите в папку `/i/webpack/` и сделайте `npm run dev` (или `npm run build`) чтобы создать скомпилированные js-файлы для локалки (или сервера)<br>
  То что скомпилировано webpack-ом автоматически подключается в главном шаблоне сайта и проходит мимо сборщика extraPacker
  Фронтенд на jQuery 4: удалённые в нём `$.isArray`, `$.trim` и т.п. для старых плагинов возвращает `i/webpack/src/jQueryCompat.js`, в своём коде их не использовать

## Что такое ExtraPacker:
### Кратко
Это своего рода webpack только встроенный в движок и объединяющий header-ы в компонентах страницы, а так же склеивающий напрямую подключённые на страницах js/css-ки.

### Подробнее и с примером
  ExtraPacker - собирает все подключенные css/less/js-файлы в html-е (кроме тех что перечислены как исключения в `core/config/extrapacker.php`, а по умолчанию там перечислены файлы созданные webpack-ом)
  и пакует их в один файл ссылку на который вставляет в head-раздел.<br>
  Так же micron собирает все head-разделы объявленные в компонентах в один, что позволяет писать код в head-раздел прямо из компонента.<br>
  Пусть у нас есть такой html-код компонента:

```html
<head>
   <link rel="stylesheet" type="text/css" href="/i/css/my_css.css" />
   <link rel="stylesheet" type="text/css" href="/i/css/my_less.less" />
   <script src="/i/js/my_js.js"></script>
   <script type="text/javascript">
      call_function_from_my_js();
   </script>
</head>
<div>
   Html-код компонента.
   <button onclick="call_function_from_my_js();">Вызов ф-ии из /i/js/my_js.js</button>
</div>
```
Micron в данном случае:

- скопирует код файла /i/js/my_js.js в общий js-файл (+ минифицирует его)
- скопирует код файла /i/js/my_css.css в общий css-файл (+ минифицирует его)
- преобразует /i/js/my_less.less в css и скопирует полученный css в общий css-файл (+ минифицирует его)
- пересоберёт общий файл, как только изменится любой подключённый файл (у less - в том числе файлы из его @import)
- подключит общие, минифицированные js/css файлы в главном шаблоне
- head-раздел объявленный в компоненте перенесёт head-раздел главного шаблона (чтобы на полученный странице был только один <head>...</head>)

### Middleware
Путь 1:
- Создайте файл в /middleware/ с нужным middleware
- Подключите его в /core/init/router.php

Путь 2:
- Создайте файл в /core/init/какой-нибудь-файл.php и поместите в него вызываемый код.
  Обратите внимание, что данный код в init-файле вызывается на каждый запрос, а это значит что если вам нужно подключить к определённым url-ам, а не ко всем, то:<br>
  либо объявите ф-ю и подключите в /core/init/router.php согласно Пути 1<br>
  либо определите правило отбора нужных url-ов if-ом прямо в вашем, созданном файле<br>

### Debug-panel и бенчмарк
При `DEBUG_MODE=1` внизу страницы (справа в свёрнутом виде) выводится debug-panel сайта, в которой можно посмотреть запросы, время исполнения, настройки сайта, подключённые файлы и пр. В ответы без главного шаблона (JSON, AJAX) панель не добавляется.<br>
Клик по времени/памяти открывает бенчмарк: время и память по этапам запроса, по каждому компоненту и каждому запросу к БД, а так же итог отдельно для PHP, БД и внешних сервисов.<br>
Свои замеры: `BM('Services / Название')` в начале и ещё раз в конце участка кода (метки, начинающиеся с `Services / `, попадают в итог по сервисам).

### Секции `<bottom>`
Аналогично `<head>`, компонент может написать `<bottom>...</bottom>` - содержимое всех таких секций собирается и вставляется перед `</body>` (удобно для скриптов, которым нужна вся разметка страницы).

### Кеш запросов к БД
`$db->select(AddDbCache("SELECT ..."))` - запрос кешируется (по умолчанию на время одного запроса к сайту, см. `pCacheFunc` в `core/config/db.php`).

### Создание таблиц моделями
Модель создаёт свою таблицу сама (`CREATE TABLE IF NOT EXISTS` в `createTable()`), но только один раз: список уже созданных таблиц хранится в `tmp/db_tables_created_*.json` (`lib/DbTablesCache.php`), и дальше на запросах `CREATE TABLE` не выполняется. Список сбрасывается сам после применения миграций и при ошибке «таблица не существует» (например, БД пересоздали) - на следующем запросе модели проверят таблицы заново. Сбросить вручную - удалить этот файл.

### Локальная разработка (`ENV=local`)
При `ENV=local` в .env SMS не отправляются, а пишутся в `tmp/sms_mockup.log`, геолокация по IP отдаёт тестовые данные, service worker PWA не регистрируется. Проверка в коде: `IsLocalEnv()`.

### Полезные классы и хелперы
- `FlashParam` - значение, которое переживёт редирект: `(new FlashParam())->set('msg', 'Сохранено')`, на следующей странице `->get('msg')`
- `BreadCrumb::getInstance()->add(['link' => SiteRoot('catalog'), 'text' => 'Каталог'])` - хлебные крошки (выводятся в главном шаблоне, если шагов больше одного)
- `SendNotice($user, 'Текст', ['telegram', 'email', 'sms'])` - уведомление по всем включённым и подтверждённым у пользователя каналам
- `GenNewCaptchaCode()` / `CheckCaptchaCode(Post('captcha_code'))` - картинка-капча; `CheckRecaptchaCode(Post('g-recaptcha-response'))` - Google reCAPTCHA (ключи `RECAPTCHA_SITE_KEY`/`RECAPTCHA_SECRET_KEY` в .env)
- `GeneratePinCode($user)` / `CheckPinCode($user, GetCodeFromForm())` - одноразовые коды подтверждения

### Мобильные приложения (apk)
Скомпилированные версии кладутся в `apps/` с номером версии в имени: `apps/1.0.9.apk`, `apps/1.0.10.apk`. Если приложений несколько, то каждое в своей под-папке (`apps/courier/1.0.2.apk`) и дальше передаётся `app=courier`.
- `/get_app` - скачать последнюю версию (файл назовётся `app_1.0.10.apk`). Папка `apps/` снаружи напрямую недоступна, поэтому, если в .env задан `APP_DOWNLOAD_KEY`, скачать можно только по ссылке `/get_app?key=...`
- `api/v1.0/get_last_app_version` - номер последней версии, чтобы приложение само проверяло обновления
- `GetLastAppVersion('courier')` - то же самое в коде (версии сравниваются через `version_compare`, поэтому 1.0.10 новее 1.0.9)

- `_dev/simple_captcha_code`, `_dev/simple_captcha_code_in_modal_wnd` - капча-картинка (`['captcha' => GetCaptchaInstance()]`); `_dev/simple_captcha_code_2`, `_dev/simple_captcha_code_2_in_modal_wnd` - Google reCAPTCHA
- `_dev/pin_code_block` - поля ввода одноразового кода (автопереход, вставка из буфера, автосабмит, таймер повторной отправки); на странице нужно Vue-приложение с `mixins: [window.pinCodeForm]`
- `_dev/rating_stars` - звёзды рейтинга (`['rating' => 3, 'jsCallback' => 'onRate']`)
- `_dev/bootstrap_validator` - валидация форм на клиенте
- `_dev/jqueryui` - jQuery UI 1.14 (календарь с русской локализацией, slider, sortable, draggable, autocomplete, dialog, tabs…), подключён на всех страницах в `tpl/_common_head.php`; поля `.datepicker` становятся календарями сами; `$.fn.button` отдан jQuery UI, бутстраповский - `$.fn.bsButton`
- `_dev/scroll_to` - плавная прокрутка (`$.scrollTo('#id', 500, {offset: -70})`, `$('.box').scrollTo(...)`, атрибут `data-scroll-to`), подключается на нужной странице
- `_dev/pwa` (в `<head>`) и `_dev/network_status` - PWA и индикатор сети; `manifest.json` и `service_worker.js` кладутся в корень сайта и подключаются, только если они есть

### Админка
Находится по адресу /_admin<br>
Первый админ создаётся из `ADMIN_DEFAULT_LOGIN`/`ADMIN_DEFAULT_PASSWORD` в .env (только если в БД ещё нет ни одного админа)<br>
Если у вас не получается войти, то проверьте что cookie сохраняются в вашем браузере

### Служебные компоненты (начинаются с `_`)
Компоненты, у которых любая часть пути начинается с `_` (`_main_tpl`, `_seo`, `_dev/...`), по url-у не открываются - они подключаются только из кода через `IncludeCom()`.<br>
Исключения заданы явными маршрутами в `core/init/router.php`:
- `/_admin/*` - админка (только для авторизованного админа). Там же тесты отправки писем/SMS/push: `/_admin/tests/*`
- `/_cron/*` - задачи по расписанию. Доступны админу или по ключу: `wget -qO- "https://site.ru/_cron/db_backup?key=CRON_SECRET"` (или заголовок `X-Cron-Key`)
- `/_telegram_bot_hook` - webhook бота. Принимается только с заголовком `X-Telegram-Bot-Api-Secret-Token`, поэтому при подключении передайте `secret_token=TELEGRAM_WEBHOOK_SECRET` в `setWebhook`
- `/_crop_image` - обрезка загруженной картинки (только для авторизованных)

Примеры (`/examples/*`) открываются только при `DEBUG_MODE=1`.

### Авторизация и безопасность
- У пользователей паролей нет: вход на сайт и в приложение - по логину (по умолчанию равен e-mail) и 6-значному одноразовому коду из письма (`UserAuthCodeModel`). Сайт: `user/login` → `user/_email_code`. Приложение: `api/v1.0/send_login_code` (login) → `api/v1.0/login` (login + code) → token
- Пароли есть только у админов (`PasswordAuthTrait`, `password_hash()`; старые md5-хеши принимаются и пересохраняются)
- После входа клиент получает случайный токен сессии (таблица `auth_tokens`, в БД лежит только его sha256): на сайте - в HttpOnly cookie с `SameSite=Lax`, в API - в ответе `api/v1.0/login`, дальше его нужно передавать в заголовке `API-User-Auth-Token`. Выход - `api/v1.0/logout`
- Коды из писем: 6 цифр, действуют 15 минут, 5 попыток, одноразовые (настройки в `core/config/user_model.php`)
- CSRF: изменяющие запросы (POST и пр.) с чужих сайтов отклоняются (проверка `Sec-Fetch-Site`/`Origin`/`Referer`), а переходы в админку с чужих сайтов открывают главную админки, не выполняя действие из ссылки
- Изменяющие действия в админке (удалить, очистить, открыть/закрыть сайт) - только POST: кнопки рисует `PostActionButton()`, ссылка-действие не выполняется (её дёргают prefetch, расширения и сканеры)
- Текущий маршрут берётся из `REQUEST_URI` (`Request::getQuery()`), а не из `$_GET['micron_query']`: этот параметр может прислать кто угодно, а по нему проверяются права админки и кабинета
- CORS: кросс-доменные запросы разрешены только доменам из `CORS_ALLOWED_ORIGINS`
- Подбор пароля: после 10 неудачных попыток на один логин или 30 с одного IP за 15 минут вход в админку и в приложение (`api/v1.0/send_login_code`, `api/v1.0/login`) блокируется (таблица `login_attempts`, лимиты в `core/config/security.php`)
- IP посетителя (`GetClientIP()`) берётся из `REMOTE_ADDR`. Если перед сайтом стоит прокси (nginx, балансировщик), впишите его IP в `TRUSTED_PROXIES`, тогда будет учитываться `X-Forwarded-For`
- Редиректы "обратно" (`back_url`) - только на страницы своего сайта: `SafeRedirectUrl($url, $default)`
- Смена e-mail, телефона или телеграма через API сбрасывает их подтверждение; пустой e-mail задать нельзя (на него приходит код для входа)
- Капча одноразовая: после проверки код больше не подходит
- В лог ошибок не попадают пароли, токены и значения cookie. В продакшене warning/notice/deprecated только пишутся в лог-файл, а в `DEBUG_MODE` останавливают скрипт (настройка `stop_on_warnings`)

### Миграции БД
Файлы `core/migrations/NNNN_описание.php` возвращают `function ($db) { ... }`. Новые миграции применяются автоматически при первом запросе после обновления кода (под `flock` - два параллельных запроса не применят их одновременно), а так же их можно посмотреть и запустить в админке: `/_admin/migrate`. Пишите миграции так, чтобы их можно было запускать повторно (`Migrator::tableExists()`, `Migrator::columnExists()`)

### Магазин и оплата
Деньги - целые копейки везде: в БД (`BIGINT`), в моделях, расчётах и JS; проценты - в сотых долях процента (7,5% = 750). Рубли - только на входе (формы, таблица импорта: `ShopKopecks()`) и выходе (`ShopPrice($kopecks)`, `ShopRubles()` для полей и фидов, банкам - `amountToBankFormat()`). Картинки товаров - в пропорции `Config('shop')['image_ratio']` (3:4, высота больше ширины): так их обрезает админка и показывает витрина.

Варианты товара: у товаров с одним кодом `variant_group` (например, часы в 3 цветах или платье S/M/L) на карточке появляется переключатель по характеристикам, которые у них различаются; «Цвет» показывается картинками (`Config('shop')['variant_image_params']`), остальное - кнопками, при смене цвета размер сохраняется. «Покупают вместе» на странице товара и «Добавьте к заказу» в корзине: сначала артикулы из поля `related`, потом то, что покупали вместе в оплаченных заказах. Остатки: если у товара задан остаток (`track_stock`), он списывается при создании заказа (с блокировкой строки), возвращается при отмене, товар без остатка нельзя купить, в каталоге он в конце и есть фильтр «Только в наличии». Брошенные неоплаченные заказы отменяет `/_cron/shop_cancel_unpaid` (`unpaid_order_ttl_hours`). Плюс «Вы недавно смотрели» (`ShopRecentlyViewed`). Всё это задаётся в админке товара и колонками импорта: «Группа вариантов», «Покупают вместе», «Остаток».

Витрина: поиск (`/shop?q=...`, он же поиск из меню), фильтры по цене и характеристикам (`Config('shop')['filter_params']`, по умолчанию - все характеристики, где от 2 до 20 разных значений), сортировка, быстрый просмотр в модальном окне (`/shop/quick_view?id=N`), избранное (`/shop/favorites`, `ShopFavorites`: у гостя в сессии, у пользователя в БД, при входе переносится), корзина и избранное без перезагрузки страницы (`i/webpack/src/shop.js`), индикатор корзины в меню с количеством и суммой. Картинки товаров (`ShopImage`) загружаются в админке, уменьшаются до 1600px и превью 600px и лежат в `upl/shop/products/{id}/`; картинки больше 40 Мпикс отклоняются (чтобы «бомба» из заголовков не съела память), а если файл не записался - это ошибка, а не битая ссылка в товаре. Вход из магазина возвращает покупателя обратно (`user/login?back_url=...`, `RememberAuthBackUrl()`). Стили - `i/scss/shop.scss` (после правок: `npm run build` в `i/webpack`).

Каталог без строки поиска фильтруется в SQL: категория (с подкатегориями), цена, «только в наличии» и характеристики (`JSON_EXTRACT` по `params`), там же сортировка и `LIMIT` - в память попадает только текущая страница. Фасеты и диапазон цен считаются отдельным лёгким запросом. Со строкой поиска релевантность по-прежнему считает `ShopSearch` в PHP: стемминг и исправление раскладки в SQL не выразить.

Категории, единицы измерения, поиск, отзывы, сравнение, промокоды, доставка, SEO (подробно - `/manual?p=shop`):
- **Категории** (`ShopCategoryModel`): дерево, адрес `/shop/c/<slug>`, в категории - товары и всех подкатегорий; ведутся в «Магазин → Категории» или колонкой импорта «Категория» (`Одежда / Футболки`, недостающие создаются).
- **Единицы измерения**: цена - за единицу товара (`unit`: шт, м, м², кг, г, л, уп - `Config('shop')['units']`), количество в корзине - с шагом `qty_step` (не меньше `min_step` единицы, по умолчанию 1) и минимальным заказом `qty_min`. Остаток и количество в заказе - `DECIMAL`, в чек уходит дробное количество, у ЮKassa - и код меры по ФФД 1.2 (`receipt.send_measure`).
- **Поиск** (`ShopSearch`): слова в любом порядке, без окончаний («футболки» -> «футболка»), исправление раскладки («nrfym» -> «ткань»), по названию/артикулу/категории/характеристикам/описанию с сортировкой по релевантности; подсказки в строке поиска в шапке (`/shop/suggest`).
- **Отзывы** (`ShopReviewModel`): оценка 1-5 и текст от вошедших пользователей, отметка «Покупатель», модерация в «Магазин → Отзывы», рейтинг у товара (`rating`, `reviews_count`) и сортировка по нему.
- **Промокоды** (`ShopPromoCodeModel`, «Магазин → Промокоды»): процент или сумма, минимальная сумма, лимит использований, срок; скидка раскладывается по ценам позиций, чтобы чек сходился. При отмене заказа использованный раз промокода возвращается (`is_promo_returned`), при возврате заказа из «Отменён» - снова расходуется; если промокод перестал подходить, оформление показывает причину, а не молча считает полную цену.
- **Доставка и оплата** (`ShopDelivery`, `Config('shop')['delivery']`, `['payment_methods']`): способы с ценой и «бесплатно от», адрес, оплата онлайн или при получении (такие заказы не отменяются кроном); доставка - отдельной позицией чека. Письмо покупателю при смене статуса в админке.
- **Похожие товары**: артикулы из поля `similar`, дальше - из той же категории с близкой ценой.
- **Доп. товары и услуги** (`ShopAddonModel`, группы - `ShopAddonGroupModel`): подарочная упаковка, гарантия, ремешок... Цена фиксированная или % от цены товара (округление вверх до `addons.percent_round`), картинка 200×200. К товару подключаются группами (в админке или колонкой импорта «Доп. услуги», названия через «;»), дубли из разных групп убираются. На карточке - блоки, выбираются кликом, цена пересчитывается сразу; в корзине товар с разным набором услуг - разные строки, в заказе и чеке услуги - отдельные позиции.
- **Картинки в админке** - онлайн-загрузчик `_ajax_upload` с обрезкой `_crop_image`: товар - в пропорции `Config('shop')['image_ratio']` (3:4, высота больше ширины), доп. услуга - квадрат.
- **Сравнение** (`ShopCompare`, `/shop/compare`), **«Сообщить о поступлении»** (`ShopStockSubscriptionModel`, письмо, когда товар снова в наличии; `/_cron/shop_stock_notify`).
- **SEO**: адрес товара `/shop/p/<id>-<название>` (старый `/shop/product?id=N` - 301), title/description, canonical, `noindex` у поиска и фильтров, schema.org `Product` и Open Graph, `/sitemap.xml` (`core/config/sitemap.php`), YML-фид `/shop/feed_yml`, `/robots.txt` генерирует движок (`src/robots.php`, правила - `core/config/robots.php`): на боевом сайте - правила и `Sitemap:` с доменом из `SITE_DOMAIN` в `.env`, при `ENV=local` и на тестовых адресах (localhost, `*.local`, `*.test`, dev/test/staging/qa/preview в имени хоста) - `Disallow: /`.

Готовая заготовка: каталог `/shop`, товар `/shop/p/<id>-<название>`, корзина `/shop/cart` (в сессии, `ShopCart`), оформление `/shop/checkout` (можно без регистрации), заказ `/shop/order?id=N&key=...`, «Мои заказы» в кабинете (`/user/orders`). В админке: «Магазин → Товары», «Заказы» (статус заказа, платежи, проверка оплаты в банке), «Категории», «Отзывы», «Промокоды». Настройки - `core/config/shop.php`, письма менеджерам - `SHOP_MANAGER_EMAILS` в `.env`.

Модели: `ShopProductModel`, `ShopOrderModel` (implements `IShopOrderModel`), `ShopOrderItemModel` (название и цена копируются из товара на момент заказа), `PaymentModel`. Таблицы создаются сами при первом обращении к модели. Гость открывает свой заказ по ссылке с секретным ключом (`$order->url()`), пользователь - свои заказы и без ключа. Смена статуса заказа (`ShopOrderModel::setStatus()`) идёт в транзакции с блокировкой строки заказа: крон отмены не отменит уже оплаченный заказ, остаток и промокод возвращаются ровно один раз, а «оживление» отменённого заказа не уводит склад в минус. Оформление защищено одноразовым токеном формы - двойной submit не создаёт второй заказ.

Импорт товаров из таблицы (`lib/ShopProductImporter.php`): админка «Магазин → Импорт товаров» - из Google-таблицы (`SHOP_IMPORT_GOOGLE_SHEET_URL` в `.env`, доступ «Все, у кого есть ссылка») или из CSV-файла (Excel с `;` тоже подходит), по расписанию - `/_cron/shop_import`. Первая строка - заголовки: `vendor_code`/Артикул, `name`/Название, `price`/Цена (обязательные), `price_old`/Старая цена, `description`/Описание, `sort`/Порядок, `is_active`/В продаже, `variant_group`/Группа вариантов, `related`/Покупают вместе (артикулы через запятую), `stock`/Остаток (пусто - не учитывать), `category`/Категория, `unit`/Единица, `qty_step`/Шаг, `qty_min`/Минимум, `similar`/Похожие, `images`/Картинки (ссылки или имена файлов из `SHOP_IMPORT_IMAGES_SOURCE` - публичная папка Яндекс Диска, начало ссылки или папка на сервере; качаются после импорта порциями, повторно не качаются; ход, очередь и нескачанные файлы с причиной - на странице импорта, журнал - `tmp/shop_images.log`), колонки `# ...` не импортируются, и характеристики с префиксом `P: ` (`P: Состав`, `P: Цвет`). Товар ищется по артикулу, пропавшие из таблицы снимаются с продажи. Если заголовки неправильные или нет ни одной правильной строки - каталог не меняется, ошибочные строки пропускаются и перечисляются в отчёте. Кнопка «Выгрузить каталог (CSV)» (`/_admin/shop/export`) отдаёт весь каталог в этом же формате - его можно загрузить в Google-таблицу и дальше вести там; выгрузка и обратный импорт каталог не меняют.

Оплата: драйвер выбирается в `core/init/pay_system.php` (ЮKassa или Сбер, ключи `PAY_SYSTEM_*` в `.env`, параметры чека в `core/config/pay_systems/*`). Путь покупателя: `pay_system/pay_form` → банк → `pay_system/waiting` → `succeeded` / `failed`. Статус платежа приходит тремя путями: возврат покупателя, уведомление банка на `/pay_system/notify` (адрес нужно указать в ЮKassa: «HTTP-уведомления», события `payment.succeeded` и `payment.canceled`; в Сбере - callback-уведомления) и крон `/_cron/pay_system_check` для зависших платежей. Уведомлению не верим - статус всегда перепроверяется запросом к банку. Статус меняется только через `PaymentModel::applyStatus()`, и обработчики `Config(['pay_system', 'on_paid'])` / `Config(['pay_system', 'on_failed'])` (по умолчанию - `ShopOrderModel::onPaymentPaid/onPaymentFailed`: статус заказа и письма) выполняются ровно один раз, даже если все три пути сработали одновременно. Свой тип заказа: реализуйте `IShopOrderModel` и поменяйте обработчики.
